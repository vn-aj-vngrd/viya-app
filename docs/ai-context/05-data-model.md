# 05 Data Model

## Purpose

This document defines the core Viya entities. Use these names and field meanings consistently across the app, Convex schema, UI components, AI prompts, and API contracts.

## Entity overview

- User
- UserPreferences
- Trip
- TripMember
- ItineraryDay
- ItineraryItem
- Booking
- TravelDocument
- ReadinessItem
- ReadinessScore
- Risk
- Task
- Moment
- WrappedSummary
- ViyaInsight
- AIConversation
- AIMessage

## User

Represents an app user.

Fields:

- `id`
- `name`
- `email`
- `avatarUrl`
- `createdAt`
- `updatedAt`

## UserPreferences

Stores traveler preferences.

Fields:

- `userId`
- `travelStyle`: `relaxed | balanced | packed | adventure | luxury | budget`
- `pacePreference`: `slow | moderate | fast`
- `budgetPreference`: `budget | midRange | premium`
- `foodPreference`
- `accessibilityNeeds`
- `notificationPreference`
- `preferredStartTime`
- `preferredRestLevel`

## Trip

Main trip entity.

Fields:

- `id`
- `ownerId`
- `title`
- `destination`
- `startDate`
- `endDate`
- `arrivalTime`
- `departureTime`
- `budgetAmount`
- `budgetCurrency`
- `travelStyle`
- `pace`
- `groupType`: `solo | couple | family | friends | work | custom`
- `status`: `draft | planning | ready | active | completed | archived`
- `readinessScore`
- `coverImageUrl`
- `summary`
- `createdAt`
- `updatedAt`

## TripMember

Represents a user or invited traveler in a shared trip.

Fields:

- `id`
- `tripId`
- `userId` optional
- `name`
- `email` optional
- `role`: `owner | editor | viewer`
- `readinessStatus`: `notStarted | inProgress | ready`
- `joinedAt`

## ItineraryDay

Represents one day in the trip.

Fields:

- `id`
- `tripId`
- `date`
- `dayNumber`
- `title`
- `summary`
- `theme`
- `estimatedCost`
- `pace`: `light | balanced | packed`
- `weatherNote`

## ItineraryItem

Represents a scheduled activity, transfer, meal, rest period, or note.

Fields:

- `id`

- `dayId`
- `title`
- `description`

- `locationName`
- `address`

- `longitude`
- `startTime`
- `endTime`
- `durationMinutes`
- `estimatedCost`

- `priority`: `required | recommended | optional`
- `status`: `planned | confirmed | skipped | completed`

## Booking

Fields:

- `id`
- `tripId`

- `startDateTime`
- `endDateTime`
- `locationName`

- `cost`
- `currency`
- `status`: `pending | confirmed | cancelled | unknown`

- `notes`

## TravelDocument

Represents documents or files needed for travel.

Fields:

- `tripId`
- `type`: `passport | id | visa | insurance | ticket | voucher | qr | permit | other`

- `createdAt`

## Data model rules

- Do not create duplicate models with different names for the same concept.
- Do not put AI-only fields randomly into UI state. Use structured payload fields.
- Use enums consistently.
- Do not store weather, flight, or booking facts as confirmed unless data came from user input, document extraction, or a verified provider.
- Keep demo data clearly marked as demo data.
