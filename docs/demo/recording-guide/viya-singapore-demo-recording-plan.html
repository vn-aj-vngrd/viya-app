Flow at a glance

The walkthrough follows one connected path.

The recording is easiest to follow as a single workspace journey. Each step adds context that the next module can use.

This is a demo scenario using synthetic Singapore trip data. It is meant to show the product flow, not real reservations.
1Home

Start from the dashboard and open the trip planning entry point.

2Create Trip

Answer the destination, dates, travelers, budget, and trip style questions.

3Ask Viya

Use the trip agent to ask, generate, adjust, and stage workspace updates.

4Workspace

Open the trip overview and confirm the core modules are connected.

5Modules

Review itinerary, budget, Vault files, and linked trip evidence.

6Readiness

Finish by checking that the trip is prepared for travel.

Viewer note: The important shift is that chat output does not stay in chat. Viya turns answers and files into workspace state.

Start the trip

Home and Create Trip set the structure.

The first part of the recording shows the user entering the trip flow and giving Viya enough information to create a useful workspace.

Watch for the question flow: destination first, then the details needed to organize the workspace.
  1. Home. Open the Trips area from the dashboard.
  2. Create Trip. Answer the planning questions instead of starting from a blank chat.
  3. Trip overview. Confirm that the trip now has a workspace with connected modules.
  4. Next action. Move into Ask Viya to generate and refine the workspace content.

Use Ask Viya

The agent updates the workspace, not just the conversation.

Ask Viya can answer trip questions, organize files, create drafts, and stage changes that the user can review before applying.

Use Ask Mode for questions. Use Agent Mode when Viya should generate, adjust, audit, or stage workspace updates.
Viewer note: The user stays in control. Viya proposes changes, and the workspace shows what has been created or updated.

Open the core modules

Itinerary, Budget, Vault, and Readiness each carry part of the trip.

This section of the recording shows the user moving through the workspace and checking the practical travel details.

The Vault is the proof layer. Budget tracks spend. Itinerary gives the schedule. Readiness confirms what is still missing or complete.
ItineraryShows the plan in days, stops, and timing.
BudgetKeeps trip costs visible and grounded.
VaultStores documents and proof for the trip.
ReadinessTurns the workspace into a final travel check.

End state

The recording ends when the trip is prepared.

  • Overview. The trip workspace shows progress and module status.
  • Itinerary. The traveler can see what happens each day.
  • Budget. The traveler can see the spend plan and linked receipt evidence.
  • Vault. The traveler can keep trip documents in one place.
  • Readiness. The traveler can confirm whether anything still needs attention.
